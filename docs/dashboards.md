# 多连接 Dashboard

左侧的「连接」和「看板」是平行入口。切换入口只改变左侧列表；打开的看板与终端、文件编辑器一起显示在中央工作区，可以移动标签或分屏。再次打开同一个看板会定位已有标签。

原来的右侧 Monitor 继续用于当前连接。中央看板引用已保存的 SSH 连接，通过独立 SSH 会话采集，不要求先打开终端，也不会随终端标签关闭而断开。

## 创建第一张卡片

1. 先在连接管理器中保存 SSH 连接。
2. 切换到「看板」，点击「新增看板」并命名。
3. 点击「添加卡片」，填写卡片名称、选择一个或多个连接，输入非交互命令及刷新周期。
4. 显式点击「试运行」，检查各连接的标准输出、错误输出、退出码、耗时和预览。编辑表单不会自动执行命令。
5. 点击「下一步」，选择文本、数值、曲线或表格，配置字段。JSON 路径支持嵌套属性和数组索引，如 `metrics.cpu`、`devices[0].usage`。
6. 保存时一起写入采集项和卡片，随后开始周期采集。取消编辑不保存配置；关闭编辑器会取消仍在进行的试运行。

数值和曲线要求有限数字，不能直接使用 `12.5%` 等字符串。表格支持 JSON 对象数组及沿用 Monitor 的 JSON Lines 格式；可以通过「使用输出中的字段」生成映射，再调整名称与顺序。

## 复用采集项

采集项包含命令、连接集合、刷新周期和超时；卡片只定义如何显示输出。新卡片可以选择已有采集项，同一次输出供多张卡片使用，不会按卡片重复执行命令。

- 修改共享采集项时会列出受影响的卡片。可以应用到所有引用，或者复制采集项，仅改变当前卡片。
- 复制卡片默认共享采集项。复制整个看板则为看板、采集项和卡片生成独立 ID。
- 「采集项」管理窗口可以修改、复制或删除源。仍被卡片引用的源不能删除；没有可见卡片引用的源不采集。
- 采集项只在本看板内共享；不同看板引用同一个保存连接时共享专用 SSH 会话，但各自执行自己的采集项。

## 布局和采集状态

看板默认双列，可以选择一至三列。在中央内容宽度不足 680 px 时显示单列，680–999 px 时最多双列，达到 1000 px 时可以显示三列；保存的列数偏好保持不变。

「编辑布局」显示拖动手柄、上移／下移及显隐按钮。跨列拖动、改名和调整列数保留采样历史，不额外执行命令。隐藏最后一张引用某个源的卡片会停止该源。

打开看板后开始采集；切到其他标签后继续在后台采集。手动暂停会保存到配置，下次打开仍保持暂停。重启恢复的后台标签只在首次显示后开始采集；关闭看板标签会清理它的任务和内存数据，最后一个使用者关闭后释放专用 SSH 会话。

每张卡片按连接展示状态和最后成功时间。单个连接或命令失败时保留其最后成功数据，其他连接继续更新。网络错误按 10、20、40、60 秒退避；需要认证或主机密钥确认时等待用户点击重试，通过已有认证对话框处理，不在后台反复弹窗。

文本按主机切换，数值按主机展示。曲线按主机和字段筛选，每条曲线使用独立采集时间，保留最多 60 个点和最近五分钟；失败、隐藏和暂停后恢复时保留断点。表格每台主机最多保留 200 行并显示截取提示，合并结果按 50 行分页，也可以按主机筛选，因此前一台主机的大表不会挤掉后一台主机。

## Docker 示例

若要让容器数量、CPU 曲线和容器表共享一次采集，可在选定的 Docker 主机上执行以下命令。需要 Docker CLI、POSIX shell 和 `jq`，SSH 用户须能直接运行 Docker 命令。

```sh
snapshot=$(docker stats --no-stream --format '{{json .}}') || exit $?
printf '%s\n' "$snapshot" | jq -s '
  map({
    name: .Name,
    cpu: (.CPUPerc | rtrimstr("%") | tonumber),
    memory: .MemUsage
  }) as $containers |
  {
    running: ($containers | length),
    cpuTotal: ($containers | map(.cpu) | add // 0),
    containers: $containers
  }'
```

将这个源命名为「Docker 快照」，选择多个连接，刷新周期 10 秒，超时 15 秒，然后创建三张引用它的卡片：

| 卡片 | 展示 | 映射 |
| --- | --- | --- |
| 运行容器 | 数值 | `running`，小数位 0 |
| CPU 总使用量 | 曲线 | `cpuTotal`，单位 `%`，小数位 1 |
| 容器列表 | 表格 | 数组路径 `containers`；列为 `name`、`cpu`、`memory` |

CPU 为容器使用量之和，100% 对应一个核心，可以超过 100%。空容器集合会得到数量和 CPU 为 0、表格为空；Docker 失败不会被转换成零。

再创建文本卡片，单独执行 `docker info --format 'Host: {{.Name}} / Engine: {{.ServerVersion}} / Containers: {{.ContainersRunning}} running'`，按连接切换查看引擎摘要。

## 存储和边界

- 看板采用独立版本化配置 `r-shell-dashboards`，仅保存连接 ID、命令及展示配置；不复制连接凭据，不保存采样结果。
- 工作区标签格式升级为版本 2，继续读取版本 1。没有看板配置的用户保持原来的连接和 Monitor 配置。
- 损坏或较新版本的看板配置会提示错误并保留原始内容，不在下一次保存时覆盖。
- 默认刷新 10 秒、最短 5 秒；超时默认 10 秒、范围 1–60 秒。同一源在同一连接上不重叠；每个专用 SSH 会话最多两个并发命令，包括试运行，排队也计入超时。
- 单次标准输出与错误输出合计不超过 256 KiB。取消、超时、输出超限及连接关闭沿用后端独立通道的清理机制。
- 首版只引用保存的 SSH 连接。暂不支持跨主机计算、动态容器序列、历史落盘、告警、跨列卡片及看板导入导出。
