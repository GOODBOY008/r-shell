# 多连接 Dashboard

左侧的「连接」和「看板」是平行入口。切换入口只改变左侧列表；打开的看板与终端、文件编辑器一起显示在中央工作区，可以移动标签或分屏。再次打开同一个看板会定位已有标签。

原来的右侧 Monitor 继续用于当前连接。中央看板的命令卡片引用已保存的 SSH 连接，通过独立非交互通道采集，不要求先打开终端，也不会随终端标签关闭而断开。纯文本和 Markdown 卡片可独立使用，无需任何连接。

## 从内置模板开始

在左侧「看板」点击新增，或点击底部的「浏览模板」。选择模板、命名并勾选已保存的 SSH 连接，然后点击「创建并开始采集」即可使用。连接列表支持按名称或主机搜索，以及全选搜索结果。

| 模板 | 预置卡片 | 环境要求 |
| --- | --- | --- |
| Linux 主机 | 内存使用率、1/5/15 分钟负载曲线、磁盘空间、主机信息 | Linux `/proc`、`awk`、`df`、`hostname`、`uname`、`uptime` |
| Docker 集群 | 运行容器、运行/停止数量趋势、容器清单、容器资源 | Docker CLI，SSH 用户能读取 Docker 守护进程；不需要 `jq` |
| 空白看板 | 无预置卡片 | 可直接添加静态说明，也可稍后配置连接与命令 |

模板选择页可以展开查看每条采集命令和间隔；浏览和切换模板不会执行命令。勾选「保存为暂停」可先生成配置，检查后手动继续。所有模板命令只读取数据，默认间隔均为 10 秒；Docker 命令超时为 15 秒。前后台保持相同的配置间隔。

模板创建的是可编辑配置副本。用户可以改变命令、连接、字段和布局，后续模板调整不会覆盖已有看板。在已有看板的「添加卡片」菜单选择「从模板添加」，会追加新的卡片和采集源，保留已有配置及暂停状态。空看板也提供模板入口。

Linux 的负载是运行或等待任务的平均数量，不是 CPU 使用百分比。Docker 资源表保留命令输出的 CPU 百分比、内存容量和网络累计量，不将字符串错误地解析为数值。若工具缺失或权限不足，卡片显示实际命令错误，可在编辑器内调整并试运行。

## 自定义第一张卡片

1. 先在连接管理器中保存 SSH 连接。
2. 切换到「看板」，点击「新增看板」，选择「空白看板」并命名。
3. 在「添加卡片」菜单选择「命令卡片」，填写卡片名称、选择一个或多个连接，输入非交互命令及刷新周期。
4. 显式点击「试运行」，检查各连接的标准输出、错误输出、退出码、耗时和预览。编辑表单不会自动执行命令。
5. 点击「下一步」，选择文本、数值、曲线或表格，配置字段。JSON 路径支持嵌套属性和数组索引，如 `metrics.cpu`、`devices[0].usage`。
6. 保存时一起写入采集项和卡片，随后开始周期采集。取消编辑不保存配置；关闭编辑器会取消仍在进行的试运行。

数值和曲线要求有限数字，不能直接使用 `12.5%` 等字符串。表格支持 JSON 对象数组及沿用 Monitor 的 JSON Lines 格式；可以通过「使用输出中的字段」生成映射，再调整名称与顺序。

## 静态文本和 Markdown

在「添加卡片」菜单选择「文本 / Markdown 卡片」，填写标题和内容。编辑器支持实时预览及插入示例；只有点击保存才更新卡片。纯文本保留原始换行和空格，Markdown 支持标题、列表、只读任务列表、表格、代码块、图片及链接。外部链接通过系统浏览器打开，不会跳走当前看板；不执行原始 HTML，链接仅支持 HTTP、HTTPS、邮件和页内引用，图片仅支持 HTTP/HTTPS。

静态卡片可以拖拽、缩放、编辑、复制、隐藏或删除，也能与命令卡片混合排列。无需选择连接、命令或刷新周期；离线及暂停采集时仍可查看。仅包含静态卡片的看板标记为「静态内容」，不会建立 SSH 会话。每张卡片内容最多 64 KiB，保存在本机配置中，复制看板时一并复制。

## 复用采集项

采集项包含命令、连接集合、刷新周期和超时；卡片只定义如何显示输出。新卡片可以选择已有采集项，同一次输出供多张卡片使用，不会按卡片重复执行命令。

- 修改共享采集项时会列出受影响的卡片。可以应用到所有引用，或者复制采集项，仅改变当前卡片。
- 复制卡片默认共享采集项。复制整个看板则为看板、采集项和卡片生成独立 ID。
- 「采集项」管理窗口可以修改、复制或删除源。仍被卡片引用的源不能删除；没有可见卡片引用的源不采集。
- 采集项只在本看板内共享；不同看板引用同一个保存连接时共享同一运行时 SSH 会话，但各自执行自己的采集项。

## 布局和采集状态

看板使用可拖拽、可缩放的网格。卡片分别占用自己的矩形区域；短卡片下方可以放入其他卡片，不再为整行保留同样的高度。初次打开旧看板和新模板时，会根据卡片类型生成合适的默认高度，并优先利用空位。

进入「编辑布局」，拖动卡片标题旁的把手移动卡片，拖动右下角改变宽度和高度。卡片吸附网格，相邻卡片自动避让并向上填补空白，松手后保存；Esc 可取消当前拖动或缩放。把手及右下角也支持方向键操作。图表和表格会利用调整后的空间，较多内容在卡片内部滚动。

「排列卡片」提供一至三列的起始排布；选择预设或「重置大小和位置」会重新整理所有尺寸下的布局。「撤销布局」恢复上一次布局操作，不撤销命令、字段或连接的编辑。隐藏卡片不占据位置，编辑状态下可从「已隐藏的卡片」恢复。隐藏最后一张引用某个源的卡片会停止该源。

宽、中、窄三种布局按实际网格容器宽度切换：1000 px 以上可放三张最小宽度卡片，640–999 px 可放两张，更窄时单列显示。每种尺寸下的位置和大小独立保存；首次切换时根据已有布局推导，单纯缩放窗口不会写入或覆盖桌面布局。拖动、缩放、重排和改名均保留采样历史，不额外执行命令。

打开看板后开始采集；切到其他标签或隐藏应用后继续在后台采集，始终使用用户配置的间隔。侧栏会显示后台状态；切换可见性不会重置采样周期或重新建连。周期从命令启动时计算，慢命令不重叠执行，错过的采样点直接跳过、不补跑。超时、退出失败和输出超限会逐步延长等待，最长为 60 秒或配置中的更长间隔；成功后恢复，显式重试可立即重试。

手动暂停会保存到配置，下次打开仍保持暂停。重启恢复的后台标签只在首次显示后开始采集；关闭看板标签会清理它的任务和内存数据，关闭后释放其 SSH 引用，最后一个使用者退出才断开传输。隐藏标签会释放图表和表格 DOM，保留筛选、分页状态及采样历史；仅包含静态卡片时没有循环采集定时器。暂停且隐藏的看板也会释放五分钟之外的历史点，清空后停止维护定时器。

看板建立运行时会话时，优先复用配置完全匹配的已连接 SSH 传输，包括终端会话。目标、用户、认证配置、代理、跳板、主机密钥策略和传输选项均需匹配；失效连接不会被复用。看板使用独立非交互通道和任务 ID。关闭终端只取消其任务和 PTY，关闭看板只取消其采集；最后一个使用者退出才断开 SSH。找不到可复用连接时正常建立新连接，普通终端登录继续使用独立传输。

原始成功输出使用共享的 8 MiB 字符内存预算（按 UTF-16 长度估算）；预算用尽时释放较旧原始输出，已解析的卡片数据仍保留。此时编辑器提示通过试运行重新获取原始预览。每个来源的一次 JSON 解码供多张卡片使用；曲线继续保留最多 60 点、最近五分钟，表格继续最多保留每连接 200 行。错误详情最多保留 4096 字符，完整试运行输出仍遵守后端 256 KiB 限额。测量方法和边界见 [Dashboard 性能验证](dashboard-performance.md)。

每张卡片按连接展示状态和最后成功时间。单个连接或命令失败时保留其最后成功数据，其他连接继续更新。网络错误按 10、20、40、60 秒退避；需要认证或主机密钥确认时等待用户点击重试，通过已有认证对话框处理，不在后台反复弹窗。

文本按主机切换，数值按主机展示。曲线按主机和字段筛选，每条曲线使用独立采集时间，保留最多 60 个点和最近五分钟；失败、隐藏和暂停后恢复时保留断点。表格每台主机最多保留 200 行并显示截取提示，合并结果按 50 行分页，也可以按主机筛选，因此前一台主机的大表不会挤掉后一台主机。

## Docker 示例

若要让容器数量、CPU 曲线和容器表共享一次采集，可在选定的 Docker 主机上执行以下命令。需要 Docker CLI、POSIX shell 和 `jq`，SSH 用户须能直接运行 Docker 命令。

```sh
snapshot=$(docker stats --no-stream --format '{{json .}}') || exit $?
printf '%s\n' "$snapshot" | jq -s '
  map({
    name: .Name,
    cpu: (.CPUPerc | rtrimstr("%") | tonumber),
    memory: .MemUsage
  }) as $containers |
  {
    running: ($containers | length),
    cpuTotal: ($containers | map(.cpu) | add // 0),
    containers: $containers
  }'
```

将这个源命名为「Docker 快照」，选择多个连接，刷新周期 10 秒，超时 15 秒，然后创建三张引用它的卡片：

| 卡片 | 展示 | 映射 |
| --- | --- | --- |
| 运行容器 | 数值 | `running`，小数位 0 |
| CPU 总使用量 | 曲线 | `cpuTotal`，单位 `%`，小数位 1 |
| 容器列表 | 表格 | 数组路径 `containers`；列为 `name`、`cpu`、`memory` |

CPU 为容器使用量之和，100% 对应一个核心，可以超过 100%。空容器集合会得到数量和 CPU 为 0、表格为空；Docker 失败不会被转换成零。

再创建文本卡片，单独执行 `docker info --format 'Host: {{.Name}} / Engine: {{.ServerVersion}} / Containers: {{.ContainersRunning}} running'`，按连接切换查看引擎摘要。

## 存储和边界

- 看板采用独立版本化配置 `r-shell-dashboards`，版本 2 增加各卡片在宽、中、窄窗口中的位置和大小，版本 3 增加静态文本卡片。继续读取版本 1 和 2，用户首次保存时才升级；不复制连接凭据，不保存采样结果。
- 工作区标签格式升级为版本 2，继续读取版本 1。没有看板配置的用户保持原来的连接和 Monitor 配置。
- 损坏或较新版本的看板配置会提示错误并保留原始内容，不在下一次保存时覆盖。
- 自定义源默认间隔 10 秒、最短 5 秒；超时默认 10 秒、范围 1–60 秒。同一保存连接上的看板命令最多同时运行一个，全部看板及试运行合计最多八个，SSH 建连最多同时四个。调度等待不创建后端任务，取消会移除尚未启动的工作；命令超时从实际发出执行请求开始，仍覆盖后端排队、通道打开、执行和读取。后端为同一物理 SSH 传输（含所有复用身份）保留最多两个采集通道的保护。
- 单次标准输出与错误输出合计不超过 256 KiB。取消、超时、输出超限及连接关闭沿用后端独立通道的清理机制。
- 首版只引用保存的 SSH 连接。暂不支持跨主机计算、动态容器序列、历史落盘、告警及看板导入导出。
